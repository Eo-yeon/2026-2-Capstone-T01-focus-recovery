# Frontend

Focus Recovery의 Frontend 영역입니다.

React 기반 Chrome Extension으로 구현하며,
사용자의 작업 목표 입력, 웹 탐색 정보 수집,
목표 이탈 발생 시 최초 목표 재제시를 담당합니다.

## 주요 기능

Frontend 영역은 다음 기능으로 구성됩니다.

### FE-001 작업 목표 입력

사용자가 작업 세션을 시작하기 전에
이번 웹 탐색의 목적을 자연어로 입력합니다.

입력한 목표는 해당 세션의 분석 기준으로 유지됩니다.

### FE-002 작업 시작

입력한 목표를 Backend에 전달하여 작업 세션 생성을 요청합니다.

세션 생성에 성공한 경우에만 탐색 정보 수집을 시작하고,
반환된 `sessionId`를 현재 활성 세션의 식별자로 사용합니다.

### FE-003 작업 종료

현재 활성 작업 세션의 종료를 Backend에 요청합니다.

정상적으로 종료된 이후에는
해당 세션의 탐색 정보 수집과 알림을 중단합니다.

### FE-004 페이지 정보 수집

활성 세션 중 분석 대상 웹페이지의 정보를
Page Visit 단위로 수집하여 Backend에 전달합니다.

주요 수집 정보는 다음과 같습니다.

- 정규화 URL
- 도메인
- 페이지 제목
- 제한된 페이지 본문
- 방문 순서
- 방문 시각
- 검색 결과 페이지 여부
- 검색어

페이지 본문은 화면에 표시되는 텍스트를 기준으로 수집하며,
분석에 필요하지 않은 요소와 민감한 입력 정보는 제외합니다.

### FE-005 체류시간 측정

분석 대상 페이지가 활성 탭이고
브라우저 창도 활성 상태인 시간만 누적합니다.

다른 탭, 다른 프로그램, 브라우저 최소화 상태에서의 시간은
활성 체류시간에 포함하지 않습니다.

### FE-006 탭 전환 감지

활성 세션 중 Chrome의 활성 탭 변경을 감지하고,
탭 전환 횟수를 탐색 행동 특징으로 기록합니다.

동일한 탭에서 URL만 변경된 경우에는
탭 전환으로 계산하지 않습니다.

### FE-007 검색어 수집

Google Search와 Naver Search의 검색 결과 페이지에서
사용자가 검색한 검색어를 추출합니다.

검색어는 URL 또는 검색 결과 페이지 구조를 통해 수집하며,
사용자의 전체 키 입력이나 검색창 입력 과정을 감시하지 않습니다.

### FE-008 목표 이탈 알림 표시

현재 활성 세션의 최종 AI 분석 결과가 `DRIFT`인 경우
사용자가 입력한 최초 작업 목표를 다시 보여줍니다.

다음 경우에는 AI 기반 목표 재제시 알림을 표시하지 않습니다.

- `NORMAL`
- `TRANSITION`
- AI 분석 실패
- 종료된 세션의 지연 분석 결과

알림이 표시되더라도 현재 웹페이지를 차단하거나
다른 페이지로 강제 이동시키지 않습니다.

### FE-009 목표 재제시 후 사용자 선택

목표 재제시 알림 이후 사용자에게 다음 선택을 제공합니다.

- 목표로 돌아가기
- 계속 탐색하기

사용자 선택은 다음 값으로 기록합니다.

```text
RETURN_TO_GOAL
CONTINUE_BROWSING
```

선택 이후에도 현재 작업 세션은 계속됩니다.

### FE-010 고정 주기 목표 알림

AI 기반 알림 방식과 비교하기 위한 사용자 평가용 기능입니다.

설정된 일정 간격마다 최초 작업 목표를 다시 보여주며,
알림과 사용자 선택은 AI 방식과 동일한 구조로 기록합니다.

## 수집 범위

Frontend는 사용자가 명시적으로 시작한
활성 작업 세션 동안에만 탐색 정보를 수집합니다.

### 분석 대상

- 공개 HTML 문서
- 검색 결과 페이지
- 기술 문서
- 블로그 및 기사
- 공개 논문 및 자료 소개 페이지

### 분석 제외 대상

- `chrome://`
- `chrome-extension://`
- 로그인 및 회원가입 페이지
- 결제 및 금융 페이지
- 개인정보 입력 중심 페이지
- Chrome 기본 PDF Viewer
- 영상 및 음성 콘텐츠 자체

### 수집하지 않는 정보

- 비밀번호
- 폼 입력값
- 쿠키
- 인증 토큰
- LocalStorage
- SessionStorage
- 클립보드
- 전체 키 입력
- 마우스 좌표
- 다운로드 파일 내용
- 전체 Chrome 방문 기록

## 처리 흐름

```text
최초 작업 목표 입력
        ↓
작업 세션 시작
        ↓
페이지 정보 수집
        ↓
체류시간 / 탭 전환 측정
        ↓
Backend 전달
        ↓
AI 분석 결과 수신
        ↓
DRIFT 여부 확인
        ↓
최초 작업 목표 재제시
        ↓
사용자 선택 기록
```

탐색 구간 구성과 AI 분석 요청은 Backend의 책임이며,
Frontend에서 임의로 최종 상태를 판단하지 않습니다.

## Backend 연동

Frontend는 Backend와 다음 데이터를 주고받습니다.

- 작업 목표
- 작업 세션
- Page Visit
- 탐색 행동 정보
- AI 분석 결과
- 알림 이벤트
- 사용자 선택

실제 API 경로, 요청·응답 형식,
오류 처리 방식은 FE·BE API 계약에서 확정합니다.

## 처리 원칙

- 활성 세션이 없으면 탐색 정보를 수집하지 않습니다.
- 세션 생성에 실패하면 수집을 시작하지 않습니다.
- 세션 종료 후에는 탐색 정보와 알림을 처리하지 않습니다.
- 검색어를 추출하지 못한 경우 임의로 추정하지 않습니다.
- AI 분석 실패를 `DRIFT`로 처리하지 않습니다.
- Context Model의 중간 판단을 알림 기준으로 사용하지 않습니다.
- 실제 표시된 알림만 Backend에 기록합니다.
- 사용자 선택으로 사이트를 차단하거나 특정 페이지로 강제 이동하지 않습니다.

## 개발 상태

현재 Frontend 영역은 기능 설계가 완료된 초기 개발 환경 구성 단계입니다.

React 및 Chrome Extension 프로젝트 구조,
의존성, 실행 방법, 빌드 방법 및 테스트 방법은
Frontend 개발 환경 구성이 완료된 이후 본 문서에 추가합니다.
