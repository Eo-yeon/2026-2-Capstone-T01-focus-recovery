# BE 기능명세서

## 1. 문서 개요

본 문서는 `BE-001.md`부터 `BE-009.md`까지의 기능 정의를 통합한 백엔드 기능명세서이다. 기존 기능 ID, 요구사항, 연관 기능 및 완료 조건을 유지하고 공통 처리 흐름과 기능 사이의 데이터 연결 기준을 정리한 문서이다.

백엔드는 Chrome Extension에서 전달한 작업 목표와 탐색 정보를 작업 세션 단위로 관리하고, Python AI Service에 탐색 구간 분석을 요청하며, 분석 결과·실제 표시된 알림·사용자 선택을 연결하여 저장하는 역할이다. 시스템 구성은 Spring Boot 기반 백엔드와 Python AI Service의 연동을 전제로 한다.

| 항목 | 내용 |
| --- | --- |
| 영역 | BE |
| 통합 대상 | BE-001~BE-009 |
| 기능 상태 | 전체 미착수 |
| 연동 대상 | FE(Chrome Extension), Python AI Service |
| 분석 단위 | 같은 세션의 최근 5개 유효 Page Visit으로 구성한 탐색 구간 |
| 구간 이동 방식 | 새로운 유효 방문마다 1개씩 이동하는 stride 1 sliding window |
| 최종 분석 상태 | NORMAL / TRANSITION / DRIFT |
| 알림 유형 | AI / FIXED_INTERVAL |

본문의 필드명은 원본 기능 정의를 정리한 논리적 명칭이다. 식별자 형식, 시간 타입·단위, 필수·선택 여부, DB 구조, API 경로·HTTP 메서드·상태 코드는 ERD 및 API 명세 단계에서 확정하는 항목이다. 원본에서 결정되지 않은 정책은 본 문서에서도 확정 사항으로 취급하지 않는다.

## 3. 공통 처리 흐름 및 규칙

### 3.1 기본 처리 흐름

1. FE가 최초 작업 목표와 작업 시작 요청을 전달하면 BE-001이 세션을 생성한다.
2. FE가 유효 Page Visit을 전달하면 BE-003이 세션과 연결하여 저장한다.
3. 방문 이후 측정한 활성 체류시간과 탭 전환 정보는 BE-006이 기존 방문에 반영한다.
4. 유효 방문이 5개 이상 누적되면 BE-009가 최근 5개 방문으로 탐색 구간을 생성한다.
5. BE-004가 최초 목표와 탐색 구간을 AI Service에 전달하고 응답을 검증한다.
6. 정상 분석 결과는 BE-007이 세션 및 탐색 구간과 연결하여 저장한다.
7. 활성 세션의 최종 결과가 DRIFT인 경우 목표 재제시 처리를 수행한다. 사용자에게 실제 표시된 알림은 BE-008이 기록한다.
8. 사용자가 알림에 응답하면 BE-005가 해당 alertId에 선택 결과를 연결한다.
9. 작업 종료 시 마지막 방문의 미반영 행동 정보를 반영할 수 있도록 처리하고, BE-002가 세션을 종료한다.

고정 주기 알림도 실제 표시 시 BE-008에 기록하고 사용자 선택은 BE-005에 저장한다. 해당 알림에는 AI 분석 결과가 연결되지 않는다.

### 3.2 세션 및 데이터 연결 규칙

- 세션의 최초 작업 목표를 해당 세션 분석의 기준으로 사용한다.
- 신규 방문 저장과 신규 분석 요청 연결은 활성 세션을 대상으로 한다. 종료된 세션은 신규 방문을 받지 않는다.
- 방문, 탐색 구간, 분석 결과, 알림 및 사용자 선택은 해당 작업 세션을 추적할 수 있어야 한다.
- 탐색 구간은 같은 세션의 유효 방문 5개를 방문 순서대로 포함해야 한다.
- 동일 URL이라도 실제 별개의 방문이면 각각 다른 Page Visit으로 저장할 수 있다.
- 분석 제외 페이지는 분석용 Page Visit으로 저장하지 않으며 탐색 구간의 방문 개수에도 포함하지 않는다.
- 사용자 선택은 분석 결과가 아니라 알림 이벤트에 연결한다. 이를 통해 두 알림 방식의 반응을 동일한 구조로 기록한다.

### 3.3 분석 실패 및 알림 규칙

- AI 통신 실패, timeout 또는 유효하지 않은 응답을 정상 분석 결과로 처리하지 않는다.
- 분석 실패 시 임의로 NORMAL, TRANSITION 또는 DRIFT를 생성하지 않는다.
- Context Model의 구조화된 출력 검증과 1회 재시도는 AI Service의 책임이다. 재시도에도 실패하면 해당 분석 전체를 실패로 처리하며 목표 재제시 알림을 발생시키지 않는다.
- AI 분석 실패가 사용자의 작업 세션을 중단시키지 않아야 한다.
- 세션 종료 이후 도착한 분석 결과는 평가 목적으로 저장할 수 있으나 새로운 사용자 알림에는 사용하지 않는다.
- 분석 결과 저장과 실제 알림 표시 기록은 별개의 처리이다. DRIFT 결과가 저장되었다는 사실만으로 실제 표시된 알림 수에 포함하지 않는다.

### 3.4 행동 정보와 종료 처리

방문 생성 시 최종 체류시간을 알 수 없으므로 페이지 정보 저장과 행동 정보 갱신을 분리한다. 행동 정보는 매초 전송하지 않고 페이지 이탈, 탭 전환, 작업 종료 등 의미 있는 이벤트를 기준으로 갱신하는 방식이다.

마지막 체류시간을 반영한 뒤 세션을 종료할 수 있어야 한다. FE가 행동 정보 갱신 완료 후 종료 요청을 전송할지, 종료 요청에 마지막 정보를 포함할지 등 구체적인 API 흐름은 미확정이다. 종료 후 지연된 행동 정보 요청을 허용할지 여부도 별도로 결정할 항목이다.

## 4. 기능별 상세 명세

### 4.1 BE-001 세션 생성

**대분류:** 작업 세션 / **상태:** 미착수

#### 기능 설명

FE에서 전달한 최초 작업 목표를 기반으로 새 작업 세션을 생성하는 기능이다. 생성된 세션은 이후 방문 기록, 행동 정보 및 AI 분석 결과를 하나의 작업 단위로 연결하는 기준이다.

#### 동작 조건 및 처리

1. FE-002 작업 시작에 따른 세션 생성 요청을 수신한다.
2. 최초 작업 목표가 존재하고 유효한지 검증한다.
3. 유효한 요청이면 새 세션을 생성하고 최초 목표 및 시작 시각을 저장한다.
4. 세션 식별자와 시작 정보를 FE에 반환한다. FE는 해당 식별자를 활성 세션으로 사용한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 생성된 작업 세션 식별자 |
| goal | 사용자가 입력한 최초 작업 목표 |
| startedAt | 작업 세션 시작 시각 |
| endedAt | 종료 시각이며 생성 시점에는 값이 없는 항목 |

#### 예외 및 제한사항

- 목표가 없거나 공백만 포함된 경우 세션을 생성하지 않는다.
- 그 밖의 유효하지 않은 목표도 세션 생성 대상에서 제외한다. 구체적인 목표 유효성 기준은 API 설계에서 확정한다.
- 동일한 목표 문자열로 여러 개의 독립 세션을 생성할 수 있다.
- 동일 목표를 다시 사용하는 경우와 동일 생성 요청의 재전송은 구분할 사항이다. 중복 요청 방지 정책의 필요 여부와 방식은 미확정이다.

#### 연관 기능

FE-001 작업 목표 입력, FE-002 작업 시작, BE-002 세션 종료, BE-003 방문 기록 저장, AI-001 목표 관련성 계산이다.

#### 완료 조건

- 유효한 최초 목표로 새 세션을 생성하고 목표 및 시작 시각을 저장할 수 있어야 한다.
- 이후 탐색 기록을 연결할 수 있는 세션 식별자를 FE에 반환해야 한다.
- 유효하지 않은 요청으로 세션이 생성되지 않아야 한다.

### 4.2 BE-002 세션 종료

**대분류:** 작업 세션 / **상태:** 미착수

#### 기능 설명

FE의 작업 종료 요청을 처리하고 대상 세션의 종료 시각을 기록하는 기능이다. 종료된 세션에는 이후 발생하는 탐색 기록이나 AI 분석 요청이 새롭게 연결되지 않도록 처리한다.

#### 동작 조건 및 처리

1. FE-003 작업 종료 요청의 sessionId로 대상 세션을 조회한다.
2. 세션이 존재하고 아직 종료되지 않았는지 확인한다.
3. 마지막 방문의 미반영 행동 정보를 반영할 수 있도록 종료 흐름을 구성한다.
4. 종료 시각을 기록하고 해당 세션을 종료 상태로 처리한다.
5. 종료 결과를 FE에 반환한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 종료 대상 세션 식별자 |
| startedAt | 작업 세션 시작 시각 |
| endedAt | 작업 세션 종료 시각 |

별도 상태 값으로 종료 여부를 관리할지 endedAt 존재 여부로 판단할지는 ERD 설계 단계에서 확정한다. 원본의 endAt 표기는 본 문서에서 endedAt으로 통일한 것이다.

#### 예외 및 제한사항

- 존재하지 않는 세션은 종료하지 않는다.
- 이미 종료된 세션에 대한 요청으로 중복 종료 처리를 수행하지 않는다.
- 종료된 세션에는 신규 방문 기록을 추가하지 않는다.
- 종료 직전 FE에 남아 있는 탐색 정보의 전송 순서와 원자적 처리 여부는 API 흐름 설계에서 확정한다.
- 브라우저 강제 종료나 네트워크 단절로 정상 종료 요청을 받지 못한 경우는 별도의 비정상 종료 정책에서 정의한다.

#### 연관 기능

FE-003 작업 종료, BE-001 세션 생성, BE-003 방문 기록 저장이며, 마지막 행동 정보 반영을 위해 BE-006과 연결되는 기능이다.

#### 완료 조건

- 유효한 활성 세션의 종료 시각을 기록하고 이후 활성 세션으로 처리하지 않아야 한다.
- 종료된 세션에 신규 탐색 기록이 추가되지 않아야 한다.
- 존재하지 않거나 이미 종료된 세션에 대한 요청으로 데이터가 잘못 변경되지 않아야 한다.

### 4.3 BE-003 방문 기록 저장

**대분류:** 탐색 기록 관리 / **상태:** 미착수

#### 기능 설명

Chrome Extension이 수집한 분석 대상 페이지 방문을 Page Visit 단위로 작업 세션에 연결하여 저장하는 기능이다. 저장된 방문은 sliding window 구성 및 AI 분석에 사용하는 데이터이다.

#### 동작 조건 및 처리

1. 활성 세션에 대한 분석 대상 Page Visit을 FE에서 수신한다.
2. 세션과 방문 데이터의 유효성을 검증한다.
3. Page Visit을 생성하고 해당 세션과 연결하여 저장한다.
4. BE-009에 탐색 구간 구성을 요청한다. 유효 방문이 5개 미만이면 구간은 생성하지 않는다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| visitId | Page Visit 식별자 |
| sessionId | 작업 세션 식별자 |
| sequence | 방문 순서 |
| normalizedUrl | 정규화 URL |
| domain | 도메인 |
| title | 페이지 제목 |
| content | 제한된 페이지 본문 |
| searchQuery | 검색어 |
| visitedAt | 방문 시각 |
| duration | 활성 체류시간 |
| tabSwitchCount | 탭 전환 행동 정보 |
| isSearchResultPage | 검색 결과 페이지 여부 |

최초 저장 시 확정되지 않은 체류시간과 일부 행동 정보는 BE-006에서 갱신하는 항목이다.

#### 예외 및 제한사항

- 존재하지 않거나 종료된 세션의 방문은 저장하지 않는다.
- 분석 제외 페이지는 분석용 방문 데이터로 저장하지 않는다.
- 같은 URL의 실제 재방문은 독립 방문으로 저장할 수 있다. 요청 재전송과 실제 재방문의 식별 방식은 별도로 확정할 사항이다.

#### 연관 기능

FE-004 페이지 정보 수집, FE-005 체류시간 측정, FE-006 탭 전환 감지, FE-007 검색어 수집, BE-006 탐색 행동 정보 갱신, BE-009 탐색 구간 구성이다.

#### 완료 조건

- 유효한 방문을 해당 세션에 연결하여 저장할 수 있어야 한다.
- 방문을 순서대로 조회하고 탐색 구간 구성 및 AI 분석에서 사용할 수 있어야 한다.

### 4.4 BE-004 AI 분석 요청 및 응답 처리

**대분류:** AI 연동 / **상태:** 미착수

#### 기능 설명

BE-009에서 생성한 최근 5개 유효 방문의 탐색 구간과 최초 작업 목표를 Python AI Service에 전달하고, 수신한 분석 응답을 검증하여 BE-007에 전달하는 기능이다.

#### 동작 조건 및 처리

1. BE-009에서 분석 가능한 탐색 구간이 생성된다.
2. 해당 세션의 최초 목표와 구간에 속한 방문 5개를 조회한다.
3. 목표, 페이지 정보, 검색어, 방문 순서 및 행동 정보를 요청 데이터로 구성한다.
4. Python AI Service에 분석을 요청한다.
5. AI Service가 의미적 관련성 계산, 탐색 맥락 분석 및 최종 분류를 수행한다.
6. BE가 응답 형식을 검증하고 유효한 결과를 BE-007에 전달한다.

실제 시스템은 유효 방문이 5개 이상 누적된 이후 새로운 유효 방문이 추가될 때마다 최근 5개를 분석하는 방식이다. Embedding 변화에 따라 Context Model 호출 횟수를 줄이는 방식은 전체 AI 응답시간 목표를 만족하지 못하는 경우 검토하는 최적화 항목이다.

#### 요청 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 작업 세션 식별자 |
| windowId | 분석 대상 탐색 구간 식별자 |
| goal | 최초 작업 목표 |
| visits | 해당 탐색 구간의 유효 방문 5개 |
| visits 내 title / content | 각 페이지 제목 및 제한된 본문 |
| visits 내 searchQuery / sequence | 검색어 및 방문 순서 |
| visits 내 duration / tabSwitchCount | 활성 체류시간 및 탭 전환 행동 특징 |

visits 내부의 실제 JSON 구조는 API 명세에서 확정하는 항목이다.

#### 응답 데이터

| 항목 | 설명 |
| --- | --- |
| pNormal | NORMAL 예측 확률 |
| pTransition | TRANSITION 예측 확률 |
| pDrift | DRIFT 예측 확률 |
| result | 최종 상태 |
| analyzedAt | 분석 수행 시각 |

Context Model을 사용하는 구성에서는 구조화된 중간 결과를 함께 전달할 수 있다. 중간 결과와 최종 분류 결과는 구분하여 취급하는 데이터이다.

#### 예외 및 제한사항

- 통신 실패 또는 timeout이면 임의의 상태를 생성하지 않는다.
- Context 구조화 출력 검증 실패 시 AI Service가 1회 재시도하며, 다시 실패하면 전체 해당 분석을 실패로 처리하고 알림을 발생시키지 않는다.
- 종료 이후 도착한 결과는 사용자 알림에 사용하지 않는다.
- BE 통신 재시도 정책과 timeout 값은 미확정이다. AI Service의 Context 출력 재시도와는 별개의 정책이다.
- 응답의 식별자 연결 방식, 확률 검증 범위·합계 허용 오차, analyzedAt 의미 등 구체적인 검증 계약은 API 명세에서 확정한다.

#### 연관 기능

BE-009 탐색 구간 구성, BE-007 AI 분석 결과 저장, AI-001 목표-페이지 의미적 관련성 계산, AI-002 최근 탐색 흐름 분석, AI-003 목표 이탈 분류이다.

#### 완료 조건

- 탐색 구간을 AI Service에 전달하고 응답을 받을 수 있어야 한다.
- 응답 형식을 검증하고 유효한 결과를 BE-007에 전달할 수 있어야 한다.
- AI 분석 실패가 사용자의 작업 세션을 중단시키지 않아야 한다.

### 4.5 BE-005 사용자 선택 결과 저장

**대분류:** 사용자 반응 관리 / **상태:** 미착수

#### 기능 설명

AI 방식 또는 고정 주기 방식의 목표 재제시 알림에 대한 사용자 선택을 해당 알림 이벤트와 연결하여 저장하는 기능이다. 두 알림 방식의 사용자 반응을 동일한 구조로 평가하기 위해 analysisId가 아니라 alertId를 연결 기준으로 사용하는 기능이다.

#### 동작 조건 및 처리

1. 유효한 알림에 대한 사용자 응답을 FE에서 수신한다.
2. alertId로 알림 존재 여부를 확인한다.
3. 선택 값을 검증한다.
4. 선택 결과를 해당 알림 및 세션과 연결하여 저장한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| feedbackId | 선택 결과 식별자 |
| sessionId | 작업 세션 식별자 |
| alertId | 대상 알림 이벤트 식별자 |
| action | RETURN_TO_GOAL 또는 CONTINUE_BROWSING |
| selectedAt | 선택 시각 |

#### 예외 및 제한사항

- 존재하지 않는 알림에 대한 선택은 저장하지 않는다.
- 동일 alertId에 대한 선택 결과가 중복 생성되지 않아야 한다.
- 중복 응답의 반환 방식과 최초 선택 이후 변경 허용 여부는 미확정이다.
- 사용자 선택은 실시간 모델 개인화에 사용하지 않는다.

#### 연관 기능

FE-009 목표 재제시 후 사용자 선택, BE-008 알림 이벤트 저장이다.

#### 완료 조건

- 사용자 선택을 해당 목표 재제시 알림에 연결하여 저장할 수 있어야 한다.
- AI 알림과 고정 주기 알림에 동일한 데이터 구조를 사용할 수 있어야 한다.

### 4.6 BE-006 탐색 행동 정보 갱신

**대분류:** 탐색 기록 관리 / **상태:** 미착수

#### 기능 설명

방문 생성 이후 FE에서 측정한 활성 체류시간과 탭 전환 등의 탐색 행동 정보를 기존 방문 기록에 반영하는 기능이다. 갱신된 행동 정보는 이후 AI 분석에 사용하는 데이터이다.

#### 동작 조건 및 처리

1. 유효한 작업 세션과 해당 세션의 기존 방문 기록이 존재한다.
2. FE가 페이지 이탈, 탭 전환, 작업 종료 등 관련 이벤트에서 행동 정보를 전달한다.
3. visitId로 기존 방문을 조회하고 요청한 세션에 속하는지 확인한다.
4. 해당 방문의 행동 정보와 갱신 시각을 반영한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 방문이 속한 작업 세션 식별자 |
| visitId | 갱신 대상 방문 식별자 |
| duration | 현재까지 측정한 활성 체류시간 |
| tabSwitchCount | 해당 방문 또는 탐색 과정의 탭 전환 정보 |
| updatedAt | 행동 정보의 마지막 갱신 시각 |

탭 전환 데이터를 단순 횟수로 저장할지 개별 이벤트로 저장할지는 ERD 및 데이터 설계에서 확정하는 항목이다.

#### 예외 및 제한사항

- 존재하지 않는 방문이나 요청한 세션에 속하지 않는 방문은 갱신하지 않는다.
- 네트워크 문제로 같은 정보가 여러 번 전달될 수 있음을 고려해야 한다.
- 체류시간을 매초 전송하는 방식은 사용하지 않는다.
- 종료 시 미반영된 마지막 방문의 체류시간을 반영한 뒤 세션을 종료할 수 있어야 한다.
- 누적값 덮어쓰기와 증가분 반영 중 어떤 방식을 사용할지, 지연·역순 요청을 어떻게 처리할지는 미확정이다.
- 이미 분석한 탐색 구간의 행동 정보가 갱신되었을 때 재분석할지 여부는 원본에 정의되지 않은 사항이다.

#### 연관 기능

FE-005 체류시간 측정, FE-006 탭 전환 감지, FE-003 작업 종료, BE-002 세션 종료, BE-003 방문 기록 저장, BE-004 AI 분석 요청 및 응답 처리, AI-003 목표 이탈 분류이다.

#### 완료 조건

- FE에서 전달한 행동 정보를 기존 방문에 정상 반영할 수 있어야 한다.
- 다른 세션이나 방문에 행동 정보가 잘못 반영되지 않아야 한다.
- 갱신된 정보를 이후 AI 분석에서 사용할 수 있어야 한다.

### 4.7 BE-007 AI 분석 결과 저장

**대분류:** AI 분석 결과 관리 / **상태:** 미착수

#### 기능 설명

AI Service가 반환한 최종 상태와 클래스별 확률을 분석 대상 탐색 구간 및 세션과 연결하여 저장하는 기능이다. 어느 구간의 분석인지 추적하여 모델 평가와 탐지 지연 평가에 사용할 수 있어야 한다.

#### 동작 조건 및 처리

1. 유효한 세션과 탐색 구간에 대한 분석이 정상적으로 완료된다.
2. 검증된 응답의 windowId 및 세션 연결을 확인한다.
3. 클래스별 확률, 최종 상태 및 분석 시각을 저장한다.
4. 최종 상태가 DRIFT이고 세션이 활성 상태이면 목표 재제시 처리로 연결한다.
5. 실제 표시된 알림은 BE-008에서 별도로 기록한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| analysisId | 분석 결과 식별자 |
| sessionId | 작업 세션 식별자 |
| windowId | 분석 대상 탐색 구간 식별자 |
| startVisitId / endVisitId | 구간의 첫 방문 및 마지막 방문 식별자 |
| pNormal / pTransition / pDrift | 클래스별 예측 확률 |
| result | NORMAL / TRANSITION / DRIFT 중 최종 상태 |
| analyzedAt | 분석 완료 시각 |

필요한 경우 사용 모델, 모델 버전 및 분석 소요시간 등을 추가 저장할 수 있다.

#### 예외 및 제한사항

- 실패한 분석을 정상 분석 결과처럼 저장하지 않는다.
- 동일 분석 요청의 중복 전달로 동일한 결과가 여러 건 생성되지 않도록 처리한다.
- 세션 종료 후 완료된 결과는 평가 목적으로 저장할 수 있으나 새로운 알림에는 사용하지 않는다.
- 분석 실패 기록을 별도로 남길지 여부, 요청 중복 식별 키 및 재분석 결과 보존 방식은 미확정이다.

#### 연관 기능

BE-004 AI 분석 요청 및 응답 처리, BE-008 알림 이벤트 저장, BE-009 탐색 구간 구성, AI-003 목표 이탈 분류이다.

#### 완료 조건

- 분석 결과를 해당 세션 및 탐색 구간에 연결하여 저장할 수 있어야 한다.
- 클래스별 확률과 최종 상태를 조회할 수 있어야 한다.
- 모델 평가 및 탐지 지연 평가에 사용할 수 있도록 분석 대상 구간을 식별할 수 있어야 한다.

### 4.8 BE-008 알림 이벤트 저장

**대분류:** 알림 관리 / **상태:** 미착수

#### 기능 설명

사용자에게 실제 표시된 목표 재제시 알림의 종류와 표시 시각을 기록하는 기능이다. 알림 횟수 및 사용자 선택 평가를 위해 실제 표시된 알림을 독립 이벤트로 관리하는 기능이다.

#### 동작 조건 및 처리

1. FE에서 실제 목표 재제시 알림이 표시된다.
2. 알림 방식과 세션을 확인한다.
3. AI 알림이면 유효한 DRIFT 분석 결과와 연결한다.
4. 고정 주기 알림이면 분석 결과 연결 없이 저장한다.
5. 알림 이벤트를 저장하고 alertId를 반환하여 이후 사용자 선택과 연결한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| alertId | 알림 이벤트 식별자 |
| sessionId | 작업 세션 식별자 |
| alertType | AI 또는 FIXED_INTERVAL |
| analysisId | AI 알림의 관련 분석 결과 식별자이며 고정 주기 알림에는 없는 항목 |
| shownAt | 사용자에게 실제 표시된 시각 |

#### 예외 및 제한사항

- AI 알림은 유효한 DRIFT 분석 결과에 연결되어야 한다.
- 고정 주기 알림에는 analysisId가 존재하지 않는다.
- 같은 알림 이벤트를 중복 저장하지 않아야 한다.
- 알림 후보 생성이나 전송만으로 실제 표시 이벤트를 기록하지 않는다.
- BE 결과를 FE에 전달하는 방식, FE 표시 완료 확인 절차 및 알림 중복 식별 방식은 미확정이다.
- 연속 DRIFT 구간에 대한 반복 알림, 알림 간 최소 간격 및 고정 주기 설정의 관리 위치는 별도로 확정할 항목이다.

#### 연관 기능

FE-008 목표 이탈 알림 표시, FE-010 고정 주기 목표 알림, BE-005 사용자 선택 결과 저장, BE-007 AI 분석 결과 저장이다.

#### 완료 조건

- 두 알림 방식을 구분하여 저장할 수 있어야 한다.
- 실제 표시된 알림 횟수를 세션 단위로 계산할 수 있어야 한다.
- 사용자 선택 결과를 개별 알림과 연결할 수 있어야 한다.

### 4.9 BE-009 탐색 구간 구성

**대분류:** 탐색 데이터 관리 / **상태:** 미착수

#### 기능 설명

같은 세션의 최근 5개 유효 Page Visit으로 AI 분석 단위인 탐색 구간을 구성하는 기능이다. 새로운 유효 방문마다 한 방문씩 이동하는 stride 1 sliding window 방식이다.

#### 동작 조건 및 처리

1. BE-003에서 새로운 유효 방문이 저장된다.
2. 같은 세션의 유효 방문 누적 개수를 확인한다.
3. 5개 미만이면 탐색 구간을 생성하지 않는다.
4. 5개 이상이면 최근 5개를 방문 순서대로 선택한다.
5. 동일 방문 조합의 구간이 중복 생성되지 않도록 처리한다.
6. 구간 식별자 및 구성 방문을 저장하고 BE-004 분석 요청으로 연결한다.

| 누적 유효 방문 | 새로 생성되는 구간 | 전체 구간 수 |
| --- | --- | --- |
| P1~P4 | 없음 | 0 |
| P1~P5 | Window 1: P1, P2, P3, P4, P5 | 1 |
| P1~P6 | Window 2: P2, P3, P4, P5, P6 | 2 |
| P1~P7 | Window 3: P3, P4, P5, P6, P7 | 3 |

유효 방문이 n개인 경우 생성되는 구간 수는 n이 5 이상이면 n-4개, 5 미만이면 0개이다. 분석 제외 페이지는 n에 포함하지 않는다.

방문 순서는 `sequence` 오름차순이며, 제외된 후보 때문에 생긴 번호 공백은 정상으로 보고 기다리지 않는다. 예를 들어 sequence 1, 3, 4, 5, 6이 저장되면 Window 1은 [1, 3, 4, 5, 6], 이후 8이 저장되면 Window 2는 [3, 4, 5, 6, 8]이다. `windowIndex`는 sequence와 별개로 구간 생성 순서다. 기존 구간은 다시 구성하지 않으므로, 구간이 생긴 뒤 마지막 구간의 끝 방문보다 작은 sequence의 신규 방문은 `409 VISIT_SEQUENCE_OUT_OF_ORDER`로 거절하고 방문과 구간을 저장하지 않는다. 이미 저장된 같은 방문의 재전송은 200이다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| windowId | 탐색 구간 식별자 |
| sessionId | 작업 세션 식별자 |
| windowIndex | 세션 내 탐색 구간 순서 |
| startVisitId / endVisitId | 구간의 첫 방문 및 마지막 방문 식별자 |
| visitIds | 방문 순서대로 구성된 5개 방문 식별자 |
| createdAt | 탐색 구간 생성 시각 |

#### 예외 및 제한사항

- 유효 방문 5개 미만이면 생성하지 않는다.
- 분석 제외 페이지는 방문 개수에 포함하지 않는다.
- 동일 방문 조합의 구간을 중복 생성하지 않는다.
- 같은 세션의 방문 저장과 구간 생성은 세션 잠금으로 직렬화한다. 구간 생성 이후 마지막 구간보다 앞선 순서로 도착한 신규 방문은 `409 VISIT_SEQUENCE_OUT_OF_ORDER`로 거절한다.
- Issue #26의 FE 로컬 구현은 후보 생성 순서를 유지하고 판정 종료 후 유효 방문에만 연속 번호를 부여한다. 이는 BE가 허용하는 sequence 오름차순 방문의 한 형태다. 실제 전송 시에는 앞선 방문의 ACK를 확인한 뒤 다음 방문을 보내야 한다. FE의 전송 지연 허용 범위·영구 전송 실패·세션 종료 ACK 순서는 여전히 협의 대상이다. 상세 경계는 [데이터 수집 규격 6장](data-collection-spec.md#6-방문-식별자와-행동-정보-갱신)을 참고한다.

#### 연관 기능

BE-003 방문 기록 저장, BE-004 AI 분석 요청 및 응답 처리, BE-007 AI 분석 결과 저장이다.

#### 완료 조건

- 유효 방문 5개 누적 시 최초 구간을 생성할 수 있어야 한다.
- 이후 새 유효 방문마다 stride 1 방식의 구간을 하나씩 생성할 수 있어야 한다.
- 각 AI 분석 결과의 대상 탐색 구간을 식별할 수 있어야 한다.

## 5. 공통 데이터 관계

다음은 논리적 연결 관계이며 실제 테이블 구조 및 제약 조건은 ERD에서 확정하는 사항이다.

| 데이터 | 연결 대상 | 연결 기준 및 의미 |
| --- | --- | --- |
| 작업 세션 | 최초 목표 | 세션의 goal을 분석 기준으로 유지하는 관계 |
| Page Visit | 작업 세션 | sessionId로 방문이 속한 작업을 식별하는 관계 |
| 탐색 구간 | 작업 세션, Page Visit 5개 | sessionId와 순서가 있는 visitIds로 구간을 구성하는 관계 |
| AI 분석 결과 | 작업 세션, 탐색 구간 | sessionId 및 windowId로 분석 대상을 추적하는 관계 |
| AI 알림 이벤트 | 작업 세션, DRIFT 분석 결과 | sessionId 및 analysisId로 연결하는 관계 |
| 고정 주기 알림 이벤트 | 작업 세션 | analysisId 없이 세션에 연결하는 관계 |
| 사용자 선택 | 작업 세션, 알림 이벤트 | sessionId 및 alertId로 연결하는 관계 |

분석 결과의 startVisitId·endVisitId는 windowId가 가리키는 구간과 일치해야 한다. 실제 구현에서 구간 경계값을 결과에 중복 저장할지 구간 조회로 제공할지는 ERD 단계에서 확정하는 사항이다.

실제 DRIFT 최초 발생 구간은 평가용 정답 라벨에서 확인할 정보이며, 저장된 예측 결과만으로 확정할 수 있는 정보가 아니다. BE-007과 BE-009는 예측 결과와 분석 구간을 추적할 수 있도록 지원하는 기능이다. 정답 라벨 연결 및 평가 데이터 구조는 별도 설계 항목이다.
