# FE 기능명세서

## 1. 문서 개요

본 문서는 `FE-001.md`부터 `FE-010.md`까지의 기능 정의를 통합한 프론트엔드 기능명세서이다. 기존 기능 ID와 요구사항을 유지하고 공통 동작 규칙, BE 연동 관계, 완료 조건 및 구현 전 확정 사항을 정리한 문서이다.

FE는 Chrome Extension에서 최초 작업 목표를 입력받고 작업 세션을 관리하며, 세션 중 분석 대상 페이지의 정보와 탐색 행동을 수집하는 영역이다. 최종 AI 분석 결과가 DRIFT이면 최초 목표를 다시 제시하고 사용자의 선택을 기록하는 역할이다. 사용자 비교 평가를 위한 고정 주기 목표 알림도 포함하는 명세이다.

| 항목 | 내용 |
| --- | --- |
| 영역 | FE |
| 통합 대상 | FE-001~FE-010 |
| 기능 상태 | 전체 미착수 |
| 구현 형태 | React 기반 Chrome Extension |
| 연동 대상 | Spring Boot 백엔드 |
| 수집 범위 | 사용자가 명시적으로 시작한 활성 작업 세션 |
| AI 분석 단위 | 최근 5개 유효 Page Visit으로 구성한 탐색 구간 |
| 최종 상태 | NORMAL / TRANSITION / DRIFT |
| 목표 재제시 방식 | AI 기반 알림 및 사용자 평가용 고정 주기 알림 |

필드명은 원본의 논리적 명칭이며 실제 타입, 시간 단위, 필수·선택 여부와 API 형식은 데이터 및 API 명세에서 확정하는 항목이다. 원본의 오탈자는 의미를 유지하여 교정한 문서이다. 모델 내부 판단과 최종 분류를 구분하며 FE-008의 NORMAL 표기는 원본의 NOMAL 오탈자를 교정한 것이다.

## 3. 공통 동작 규칙

### 3.1 작업 세션 흐름

1. 사용자가 최초 작업 목표를 입력한다.
2. 작업 시작을 선택하면 FE가 BE에 세션 생성을 요청한다.
3. 생성 성공 후 반환된 sessionId를 활성 세션으로 설정하고 탐색 정보 수집을 시작한다.
4. 분석 대상 페이지가 활성화되면 페이지 정보와 검색어를 수집하고 Page Visit으로 BE에 전달한다.
5. 활성 체류시간과 탭 전환 횟수를 측정하고 방문 기록에 연결하여 전달한다.
6. BE가 최근 5개 유효 방문으로 탐색 구간을 구성하고 AI Service에 분석을 요청한다.
7. FE는 활성 세션의 최종 DRIFT 결과를 받으면 최초 목표를 재제시한다. NORMAL은 알림하지 않으며 TRANSITION은 추가 탐색을 관찰한다.
8. 실제 표시된 알림은 BE에 기록하고 사용자 선택을 alertId에 연결한다. 선택 후 세션은 계속된다.
9. 작업 종료 요청이 정상 처리되면 수집을 중단하고 활성 세션을 해제한다.

고정 주기 평가 조건에서는 설정된 간격으로 최초 목표를 표시하며, 알림 기록과 사용자 선택은 AI 방식과 같은 구조를 사용한다.

### 3.2 목표와 세션 유지

- 최초 목표는 세션 진행 중 분석의 기준으로 유지한다.
- 목표를 변경하려면 현재 세션을 종료한 뒤 새 세션을 시작한다.
- FE에서 이미 활성 세션이 존재하면 새 작업 세션을 동시에 시작하지 않는다.
- 세션 생성 실패 시 수집을 시작하지 않는다.
- 세션 종료 실패 시 즉시 종료된 상태로 처리하지 않으며 오류 안내와 재시도를 제공해야 한다.
- 활성 세션이 없거나 종료된 상태에서는 탐색 정보를 수집하지 않는다.

### 3.3 수집 범위

| 구분 | 대상 및 규칙 |
| --- | --- |
| 분석 대상 | 공개 HTML 문서, 검색 결과 페이지, 기술 문서, 블로그·기사, 공개 논문 및 자료 소개 페이지 |
| 제외 페이지 | chrome://, chrome-extension://, 로그인·회원가입, 결제·금융·개인정보 입력 중심 페이지, Chrome 기본 PDF Viewer |
| 제외 콘텐츠 | 영상·음성 콘텐츠 자체 |
| URL | query parameter와 fragment를 기본적으로 제거한 정규화 URL |
| 본문 | 화면에 표시되는 텍스트에서 script, style, 광고, 숨겨진 요소 및 폼 입력값 등을 제외한 제한된 본문 |
| 본문 길이 | 최대 5,000자를 기준으로 하는 항목이며 원본의 일부 표기에는 ‘약 5,000자’가 사용된 사항 |
| 활성 체류시간 | 분석 대상 페이지의 탭이 활성이고 브라우저 창도 활성인 시간만 누적 |
| 검색어 추출 | Google Search와 Naver Search의 검색 결과 페이지 |
| 지원 제외 검색 | 다른 검색 서비스 및 웹사이트 내부 검색 |

비밀번호, 폼 입력값, 쿠키, 인증 토큰, LocalStorage·SessionStorage, 클립보드, 전체 키 입력, 마우스 좌표, 다운로드 파일 내용 및 전체 Chrome 방문기록은 수집하지 않는 데이터이다. 검색어는 검색 결과의 URL 또는 페이지 구조에서 추출하며 입력 과정을 감시하지 않는 방식이다.

검색어는 URL의 query parameter를 제거하기 전에 추출한다. 정규화 후 검색어를 복원하거나 임의로 추정하는 방식은 사용하지 않는다.

### 3.4 방문 및 행동 정보

페이지 수집은 Page Visit 단위이다. 같은 URL의 실제 재방문은 별개 방문으로 기록할 수 있다. 기존 탭 복귀 시 기존 방문을 재개할지 새 방문을 생성할지는 미확정이며, FE-004·FE-005·FE-006과 BE의 방문 순서 및 구간 구성 정책이 일치해야 한다.

백그라운드 탭의 열린 시간은 활성 체류시간에 포함하지 않는다. 브라우저 최소화나 다른 프로그램으로 포커스 이동 시에도 측정을 일시 중지한다. 체류시간 또는 탭 전환 횟수만으로 목표 이탈을 판단하지 않으며 의미적 관련성과 탐색 맥락을 함께 사용하는 행동 특징이다.

탐색 구간 구성과 AI 분석 요청은 BE의 책임이다. FE가 임의로 분석 결과를 생성하거나 최종 상태를 추정하는 기능은 원본에 포함되어 있지 않다.

### 3.5 알림과 사용자 선택

- AI 알림은 활성 세션의 최종 분류 결과가 DRIFT인 경우에만 표시한다. Context Model의 중간 상태를 알림 기준으로 사용하지 않는다.
- 분석 실패나 종료된 세션의 지연 응답으로 알림을 표시하지 않는다.
- 알림은 최초 목표를 다시 제시하는 방식이며 현재 페이지를 차단·종료하거나 강제 이동시키지 않는다.
- ‘목표로 돌아가기’는 복귀 의사 기록이다. 특정 페이지로 자동 이동하거나 세션 목표를 변경하는 동작이 아니다.
- ‘계속 탐색’은 현재 페이지 이용과 탐색 분석을 계속하는 선택이다.
- 사용자 선택은 analysisId가 아닌 alertId에 연결하며 실시간 모델 개인화에 사용하지 않는다.
- 실제 표시된 알림만 BE-008에 기록한다. 표시 전 후보나 수신 결과만으로 실제 알림 횟수를 증가시키지 않는다.

## 4. 기능별 상세 명세

### 4.1 FE-001 작업 목표 입력

**대분류:** 작업 세션 / **상태:** 미착수

#### 기능 설명

작업 세션 시작 전에 사용자가 이번 웹 탐색의 목적을 자연어로 입력하는 기능이다. 입력한 문자열은 세션의 최초 목표이며 이후 페이지 내용 및 탐색 흐름의 관련성 분석 기준이다.

목표 예시는 ‘캡스톤 프로젝트에 사용할 공개 인공지능 데이터셋 3개 찾기’와 ‘Spring Boot에서 JWT 인증을 구현하는 방법 조사하기’이다.

#### 동작 조건 및 처리

1. 새로운 작업 세션을 시작하려는 상태에서 목표 입력 영역을 제공한다.
2. 사용자가 입력한 목표의 유효성을 확인한다.
3. 유효한 목표이면 작업 시작 기능을 사용할 수 있도록 한다.
4. 작업 시작 시 목표를 확정하여 FE-002를 통해 BE에 전달한다.
5. 이미 진행 중인 세션의 목표는 새 입력으로 임의 변경하지 않는다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| goal | 사용자가 입력한 최초 작업 목표 |
| createdAt | 원본에 기재된 목표 기준 세션 생성 시각 |

sessionId와 실제 세션 생성·시작 시각은 FE-002 및 BE-001에서 확정하는 항목이다. createdAt을 별도 목표 필드로 둘지 세션의 startedAt과 통일할지는 데이터 명세에서 확정하는 사항이다.

#### 예외 및 제한사항

- 빈 값이나 공백만 입력한 경우 작업을 시작할 수 없다.
- 목표는 사용자가 수행하려는 작업의 목적을 자연어로 작성하는 방식이다.
- 최소·최대 글자 수는 UI 설계에서 결정하며 임의의 수치를 확정하지 않는다.
- 목표 변경은 기존 세션 종료 후 새 세션 시작으로 수행한다.

#### 연관 기능

FE-002 작업 시작, BE-001 세션 생성, AI-001 목표 관련성 계산이다.

#### 완료 조건

- 목표를 입력할 수 있고 빈 값으로는 작업을 시작할 수 없어야 한다.
- 유효한 목표로 작업을 시작하면 입력 문자열이 변경되지 않은 상태로 최초 목표에 전달되어야 한다.

### 4.2 FE-002 작업 시작

**대분류:** 작업 세션 / **상태:** 미착수

#### 기능 설명

입력한 최초 목표로 BE에 세션 생성을 요청하고 성공 시 탐색 정보 수집을 활성화하는 기능이다.

#### 동작 조건 및 처리

1. 유효한 목표가 입력되어 있고 현재 활성 세션이 없는지 확인한다.
2. 사용자가 작업 시작 버튼을 선택하면 BE-001에 세션 생성을 요청한다.
3. 성공 응답의 sessionId를 활성 세션으로 설정하고 시작 정보를 보관한다.
4. 해당 세션의 탐색 정보 수집을 시작한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| goal | 최초 작업 목표 |
| sessionId | BE에서 생성한 작업 세션 식별자 |
| startedAt | 작업 세션 시작 시각 |

식별자와 시작 시각의 실제 생성 주체 및 형식은 BE-001의 API 계약에서 확정하는 항목이다.

#### 예외 및 제한사항

- 빈 값이나 유효하지 않은 목표로 시작하지 않는다.
- 이미 활성 세션이 있으면 중복 세션을 시작하지 않는다.
- 생성 요청 실패 시 수집을 시작하지 않고 사용자에게 실패를 안내한다.
- 브라우저 종료 또는 확장 프로그램 실행 상태 변경 시 세션 처리 방식은 복구·비정상 종료 정책에서 정의한다.

#### 연관 기능

FE-001 작업 목표 입력, FE-003 작업 종료, FE-004 페이지 정보 수집, BE-001 세션 생성이다.

#### 완료 조건

- 유효한 목표로 시작을 선택하면 세션 생성 요청이 BE에 전달되어야 한다.
- 생성 성공 시 활성 세션을 설정하고 수집이 가능한 상태로 전환되어야 한다.
- 생성 실패 시 활성 세션으로 전환되지 않아야 한다.

### 4.3 FE-003 작업 종료

**대분류:** 작업 세션 / **상태:** 미착수

#### 기능 설명

현재 활성 작업 세션의 종료를 BE에 요청하고 정상 처리 후 탐색 정보 수집과 해당 세션의 분석을 중단하는 기능이다.

#### 동작 조건 및 처리

1. 현재 활성 세션이 존재하는지 확인한다.
2. 사용자가 작업 종료를 선택하면 해당 sessionId로 BE-002에 종료를 요청한다.
3. 종료 요청이 정상 처리되면 탐색 정보 수집을 중단한다.
4. 활성 세션 정보를 해제한다.
5. 이후 탐색 활동을 종료된 세션의 수집·분석 대상에서 제외한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 종료 대상 활성 세션 식별자 |
| endedAt | 작업 세션 종료 시각 |

endedAt의 실제 생성 및 저장 방식은 BE-002에서 정의하는 항목이다.

#### 예외 및 제한사항

- 활성 세션이 없으면 종료 요청을 수행하지 않는다.
- 종료 요청 실패 시 즉시 종료된 상태로 처리하지 않고 오류 안내 및 재시도를 제공한다.
- 종료 시 미전송 탐색 기록과 마지막 체류시간을 처리하는 구체적인 흐름은 별도 확정 사항이다.
- BE-006의 마지막 행동 정보 반영 요구와 맞춰 종료 요청 전 갱신 또는 종료 요청과 함께 반영하는 방식을 정해야 한다.
- 브라우저 강제 종료, 확장 프로그램 비활성화 및 네트워크 단절은 별도 비정상 종료 정책의 대상이다.

#### 연관 기능

FE-002 작업 시작, FE-004 페이지 정보 수집, FE-005 체류시간 측정, FE-006 탭 전환 감지, BE-002 세션 종료이다. 마지막 행동 정보 처리에서는 BE-006과 연동하는 기능이다.

#### 완료 조건

- 활성 세션의 종료 요청을 BE에 전달할 수 있어야 한다.
- 정상 종료 후 활성 세션이 해제되고 이후 탐색 활동이 해당 세션에 포함되지 않아야 한다.
- 종료 실패를 사용자에게 안내하고 재시도할 수 있어야 한다.

### 4.4 FE-004 페이지 정보 수집

Issue #26의 로컬 구현은 후보 생성 순서를 유지하며 판정이 종료된 앞쪽 후보의 유효 방문에만 연속 `sequence`를 확정한다. 열린 유효 방문은 `visits` 미리보기, 순서까지 확정된 방문은 `readyVisits`로 구분한다. 판정 종료 경계·제외 복구·전송 지연의 범위는 [데이터 수집 규격 6장](data-collection-spec.md#6-방문-식별자와-행동-정보-갱신)을 따른다. 실제 HTTP·영속 큐와 10초 분석 시점 연동은 후속 작업이다.

**대분류:** 탐색 정보 수집 / **상태:** 미착수

#### 기능 설명

활성 세션 중 분석 대상 웹페이지의 정보를 추출하여 Page Visit으로 BE에 전달하는 기능이다. 수집 결과는 최근 5개 방문 구간 구성 및 의미적·맥락적 분석에 사용하는 기본 데이터이다.

#### 동작 조건 및 처리

1. 활성 세션에서 새로운 페이지가 활성화되면 분석 대상 여부를 확인한다.
2. 페이지 URL, 도메인, 제목, 방문 순서 및 시각 등을 추출한다.
3. 지원 검색 결과 페이지이면 FE-007에서 검색어를 먼저 추출한다.
4. URL의 query parameter와 fragment를 기본적으로 제거한다.
5. 본문을 전처리하고 최대 5,000자 기준으로 제한한다.
6. Page Visit을 구성하여 BE-003에 전달한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| normalizedUrl | query parameter 및 fragment를 제거한 정규화 URL |
| domain | 방문 페이지 도메인 |
| title | 페이지 제목 |
| content | 전처리된 제한 본문 |
| sequence | 세션 내 방문 순서 |
| visitedAt | 페이지 방문 시각 |
| isSearchResultPage | 검색 결과 페이지 여부 |
| searchQuery | 지원 검색 결과 페이지에서 추출한 검색어 |

BE-003이 저장한 visitId를 FE-005와 행동 정보 갱신에서 사용하는 방식은 API 명세에서 확정해야 하는 사항이다.

#### 예외 및 제한사항

- 세션이 없거나 종료되었으면 수집하지 않는다.
- 3.3의 분석 제외 페이지·콘텐츠 및 수집 금지 데이터를 수집하지 않는다.
- 같은 URL의 실제 재방문은 별개의 방문으로 기록할 수 있다.
- 본문 수집은 화면 표시 텍스트를 기준으로 하며 script, style, 광고, 숨겨진 요소 및 폼 입력값 등을 제외한다.
- 정확한 문자 계산 방식과 본문 추출·페이지 판별 구현은 별도 확정 사항이다.

#### 연관 기능

FE-002 작업 시작, FE-003 작업 종료, FE-005 체류시간 측정, FE-006 탭 전환 감지, FE-007 검색어 수집, BE-003 방문 기록 저장, BE-009 탐색 구간 구성이다.

#### 완료 조건

- 대상 페이지에서 정규화 URL, 도메인, 제목, 제한 본문, 방문 순서 및 시각을 수집할 수 있어야 한다.
- 제외 대상 및 금지 데이터를 수집하지 않아야 한다.
- 하나의 Page Visit으로 BE에 전달할 수 있어야 한다.

### 4.5 FE-005 체류시간 측정

**대분류:** 탐색 정보 수집 / **상태:** 미착수

#### 기능 설명

활성 세션 중 분석 대상 페이지가 활성 탭이고 브라우저 창도 활성인 시간을 누적하는 기능이다. 페이지가 열려 있는 전체 시간과 구분하는 행동 측정이다.

#### 동작 조건 및 처리

1. 분석 대상 페이지 방문 및 활성 상태에서 체류시간 측정을 시작한다.
2. 페이지 이동, 탭 전환, 탭·창 비활성화, 작업 종료 또는 페이지 닫기 시 현재 활성 시간을 계산한다.
3. 비활성 상태에서는 측정을 일시 중지한다.
4. 페이지를 다시 활성화하면 방문 정책에 맞춰 측정을 재개한다.
5. 측정값을 해당 visitId와 연결하여 BE에 전달한다.

| 상황 | A 페이지 측정 |
| --- | --- |
| 10:00:00 A 페이지 진입 | 시작 |
| 10:00:30 B 탭으로 전환 | 30초 누적 후 중지 |
| 10:01:10 A 페이지 복귀 | 재개 |
| 10:01:40 다른 페이지 이동 | 추가 30초 누적 |

기존 방문을 재개하는 정책을 적용한 예시에서 A의 활성 체류시간은 60초이다. B 탭을 보던 40초는 A의 체류시간에서 제외되는 시간이다. 복귀를 새 방문으로 처리하는 정책에서는 방문별 기록이 달라지므로 정책 확정이 필요한 예시이다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| visitId | 해당 페이지 방문 식별자 |
| startedAt | 해당 페이지의 활성 체류 측정 시작 시각 |
| duration | 해당 방문의 누적 활성 체류시간 |

이 startedAt은 FE-002의 세션 시작 시각과 의미가 다른 값이다. 실제 필드명과 시간 단위는 데이터·API 명세에서 확정하는 항목이다.

#### 예외 및 제한사항

- 세션 시작 전 또는 종료 후에는 측정하지 않는다.
- 다른 탭·창·프로그램으로 포커스가 이동하거나 브라우저가 최소화된 시간은 포함하지 않는다.
- 복귀 시 누적 또는 새 방문 처리 방식은 FE-004와 일관되어야 한다.
- 비정상 종료나 확장 오류로 이벤트를 받지 못한 경우 정확한 계산이 어려울 수 있으며 보정 방식은 미확정이다.
- 체류시간 자체만으로 목표 이탈을 판단하지 않는다.
- BE-006의 기본 정책과 맞춰 의미 있는 이벤트에서 전달하며 매초 서버 갱신 방식은 사용하지 않는다.

#### 연관 기능

FE-002 작업 시작, FE-003 작업 종료, FE-004 페이지 정보 수집, FE-006 탭 전환 감지, BE-003 방문 기록 저장, AI-003 목표 이탈 분류이다. 생성 후 갱신되는 측정값은 BE-006과 연동하는 데이터이다.

#### 완료 조건

- 실제 활성 체류시간을 측정하고 비활성 시간을 제외할 수 있어야 한다.
- 재활성화 시 측정을 재개할 수 있어야 한다.
- 최종 측정값을 올바른 방문 기록과 연결하여 BE에 전달할 수 있어야 한다.

### 4.6 FE-006 탭 전환 감지

**대분류:** 탐색 정보 수집 / **상태:** 미착수

#### 기능 설명

활성 세션에서 Chrome의 활성 탭 변경을 감지하고 횟수를 행동 특징으로 기록하는 기능이다. 의미적 관련성 및 최근 탐색 맥락과 함께 최종 분류에 사용하는 정보이다.

#### 동작 조건 및 처리

1. 활성 세션에서 활성 탭이 변경되면 전환을 감지한다.
2. 해당 세션의 탭 전환 횟수를 증가시킨다.
3. 이전 페이지의 활성 체류시간 측정을 중지한다.
4. 새 활성 탭이 분석 대상이면 체류시간 측정을 시작하거나 재개한다.
5. 이후 세션 또는 탐색 구간에서 사용할 수 있도록 행동 정보를 기록하고 BE-006과 연동한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| tabSwitchCount | 탐색 과정의 탭 전환 횟수 |

개별 탭 이동 경로 자체가 아니라 분석 구간에서 사용할 수 있는 전환 횟수를 제공하는 것이 기본 정책이다. 세션 누적 횟수를 방문 및 구간의 특징으로 배분하는 방식은 미확정이다.

#### 예외 및 제한사항

- 동일 탭에서 URL만 변경되면 탭 전환으로 계산하지 않는다.
- 새 탭이 생성되었어도 활성화되지 않았다면 횟수를 증가시키지 않는다.
- 활성 세션이 없으면 기록하지 않는다.

#### 연관 기능

FE-005 체류시간 측정, FE-004 페이지 정보 수집, BE-006 탐색 행동 정보 갱신, AI-003 목표 이탈 분류이다.

#### 완료 조건

- 활성 탭 변경을 감지하고 횟수를 누적할 수 있어야 한다.
- 탐색 구간의 행동 특징으로 사용할 수 있는 정보를 제공해야 한다.
- 탭 전환 시 체류시간 측정 상태가 올바르게 변경되어야 한다.

### 4.7 FE-007 검색어 수집

**대분류:** 탐색 정보 수집 / **상태:** 미착수

#### 기능 설명

Google Search 또는 Naver Search 검색 결과 페이지에서 실제 검색어를 추출하는 기능이다. 검색어는 최근 탐색 의도의 변화를 분석하는 Context Model 입력에 사용하는 데이터이다.

#### 동작 조건 및 처리

1. 활성 세션의 현재 페이지가 지원 검색 서비스의 결과 페이지인지 확인한다.
2. URL 또는 검색 결과 페이지 구조에서 검색어를 추출한다.
3. 현재 Page Visit에 연결한다.
4. 검색어 추출 이후 페이지 URL을 정규화한다.
5. FE-004의 방문 데이터와 함께 BE에 전달한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| searchQuery | 검색에 사용한 문자열 |
| searchedAt | 검색 결과 페이지 방문 시각 |

searchedAt을 별도 저장할지 FE-004의 visitedAt으로 표현할지는 데이터 명세에서 확정하는 항목이다.

#### 예외 및 제한사항

- 다른 검색 서비스 및 사이트 내부 검색은 초기 지원 대상에서 제외한다.
- 전체 키 입력이나 검색창 입력 과정을 감시하지 않는다.
- 정상 추출할 수 없으면 검색어를 추정하지 않는다.
- 추출 실패 시 searchQuery의 부재 표현과 해당 방문 처리 방식은 API 명세에서 확정한다.

#### 연관 기능

FE-004 페이지 정보 수집, BE-003 방문 기록 저장, AI-002 최근 탐색 흐름 분석이다.

#### 완료 조건

- Google·Naver 결과 페이지에서 검색어를 추출하고 해당 방문과 연결할 수 있어야 한다.
- 지원하지 않는 페이지의 일반 문자열을 검색어로 잘못 수집하지 않아야 한다.

### 4.8 FE-008 목표 이탈 알림 표시

**대분류:** 목표 이탈 개입 / **상태:** 미착수

#### 기능 설명

활성 세션의 최종 분석 상태가 DRIFT인 경우 최초 작업 목표를 다시 제시하는 기능이다. 최종 상태가 NORMAL이면 알림하지 않으며 TRANSITION이면 추가 탐색을 관찰하는 동작이다.

#### 동작 조건 및 처리

1. 최종 AI 분석 결과를 수신한다.
2. 활성 세션에 속한 결과인지 확인한다.
3. 최종 result가 DRIFT이면 최초 목표를 표시한다.
4. 실제 표시 시각을 기록하고 BE-008에 알림 이벤트를 전달한다.
5. FE-009를 통해 사용자 선택을 받는다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| analysisId | DRIFT 판단 근거인 분석 결과 식별자 |
| goal | 최초 작업 목표 |
| result | 최종 DRIFT 상태 |
| shownAt | 실제 알림 표시 시각 |

알림 이벤트에는 BE-008의 AI 유형을 사용하며 반환된 alertId를 이후 사용자 선택에 연결한다. 결과 전달 방식과 alertId 확보 절차는 API 연동에서 확정하는 항목이다.

#### 예외 및 제한사항

- 분석 실패 시 표시하지 않는다.
- NORMAL 또는 TRANSITION 결과에 AI 목표 재제시 알림을 표시하지 않는다.
- 종료된 세션에 DRIFT 결과가 늦게 도착해도 표시하지 않는다.
- 이전 세션의 결과를 현재 활성 세션에 잘못 표시하지 않아야 한다.
- 현재 페이지를 차단·종료하거나 강제 이동시키지 않는다.
- 반복 DRIFT 알림의 간격·중복 처리와 알림 UI 형태는 미확정이다.

#### 연관 기능

FE-009 목표 재제시 후 사용자 선택, BE-007 AI 분석 결과 저장, BE-008 알림 이벤트 저장, AI-003 목표 이탈 분류이다.

#### 완료 조건

- 활성 세션의 최종 DRIFT 결과일 때만 AI 방식의 목표 재제시가 표시되어야 한다.
- NORMAL·TRANSITION·분석 실패·종료된 세션의 지연 결과에서는 AI 알림이 나타나지 않아야 한다.
- 알림 이후 사용자가 다음 행동을 직접 선택할 수 있어야 한다.

### 4.9 FE-009 목표 재제시 후 사용자 선택

**대분류:** 목표 재제시 / **상태:** 미착수

#### 기능 설명

AI 또는 고정 주기 목표 알림 이후 사용자가 원래 목표로 복귀할지 현재 탐색을 계속할지 선택하는 기능이다.

#### 동작 조건 및 처리

1. 현재 세션에서 유효한 목표 재제시 알림이 표시된다.
2. ‘목표로 돌아가기’와 ‘계속 탐색’ 선택을 제공한다.
3. 선택한 action과 선택 시각을 해당 alertId에 연결하여 BE-005에 전달한다.
4. 알림을 종료하고 작업 세션을 계속한다.

| 사용자 선택 | action | 의미 |
| --- | --- | --- |
| 목표로 돌아가기 | RETURN_TO_GOAL | 복귀 의사를 기록하는 선택 |
| 계속 탐색 | CONTINUE_BROWSING | 현재 이용 및 탐색 분석을 계속하는 선택 |

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 현재 작업 세션 식별자 |
| alertId | 응답 대상 알림 식별자 |
| action | RETURN_TO_GOAL 또는 CONTINUE_BROWSING |
| selectedAt | 사용자 선택 시각 |

#### 예외 및 제한사항

- 어느 선택에서도 사이트 접근을 제한하거나 특정 페이지로 강제 이동시키지 않는다.
- 사용자 선택으로 현재 모델을 실시간 개인화하지 않는다.
- 같은 알림의 선택 결과를 중복 저장하지 않아야 한다.
- 사용자 평가에서 실제 DRIFT 상태의 RETURN_TO_GOAL 선택 비율을 목표 복귀 선택률 계산에 사용할 수 있다.
- 복귀 선택은 복귀 의사이며 실제 목표 복귀 행동을 확인한 사실과 구분하는 기록이다.
- 저장 실패, alertId 발급 전 선택, 미응답·닫기 처리 및 선택 변경 허용 여부는 미확정이다.

#### 연관 기능

FE-008 목표 이탈 알림 표시, FE-010 고정 주기 목표 알림, BE-005 사용자 선택 결과 저장, BE-008 알림 이벤트 저장이다.

#### 완료 조건

- 두 선택 중 하나를 수행하고 해당 alertId에 연결하여 저장할 수 있어야 한다.
- 어느 선택에서도 웹페이지를 강제로 차단하지 않아야 한다.
- 선택 후 작업 세션을 계속할 수 있어야 한다.

### 4.10 FE-010 고정 주기 목표 알림

**대분류:** 사용자 평가 / **상태:** 미착수

#### 기능 설명

AI가 알림 시점을 결정하는 방식의 추가 가치를 비교 평가하기 위해 사전 설정된 일정 간격마다 최초 목표를 재제시하는 기능이다. 최종 서비스의 핵심 목표 이탈 판단 기능과 구분되는 사용자 평가용 기능이다.

#### 동작 조건 및 처리

1. 사용자 평가에서 세션의 알림 조건이 고정 주기 방식으로 설정된다.
2. 작업 세션 시작 후 사전 설정된 간격을 기준으로 알림 시점을 관리한다.
3. 주기가 도래하면 최초 목표를 표시한다.
4. 실제 표시 알림을 BE-008에 기록하고 FE-009에서 선택을 받는다.
5. 다음 주기를 관리하며 활성 세션에서 반복한다.

#### 데이터

| 항목 | 설명 |
| --- | --- |
| sessionId | 작업 세션 식별자 |
| goal | 최초 작업 목표 |
| shownAt | 실제 표시 시각 |

알림 기록에서는 FIXED_INTERVAL 유형을 사용하며 analysisId를 연결하지 않는다. 설정 간격 및 평가 조건의 필드·관리 위치는 별도 설계 사항이다.

#### 예외 및 제한사항

- AI 결과와 관계없이 사전에 설정된 주기에 따라 동작한다.
- 고정 주기 간격은 최종 사용자 평가 이전 파일럿에서 AI 방식과 유사한 평균 세션당 알림 횟수가 발생하도록 설정한다.
- 최종 평가 시작 이후에는 간격을 변경하지 않는다. 임의의 분 단위 값을 본 문서에서 지정하지 않는다.
- 세션이 종료되면 해당 세션의 고정 주기 알림도 중단해야 한다.
- 주기 기준 시각, 알림 응답 중 다음 주기 처리, 브라우저 비활성·재실행 상황 및 AI 알림과의 동시 표시 방지 방식은 미확정이다.

#### 연관 기능

FE-009 목표 재제시 후 사용자 선택, BE-008 알림 이벤트 저장이다.

#### 완료 조건

- 고정 주기 평가 조건에서 설정된 간격으로 최초 목표를 표시할 수 있어야 한다.
- 알림 표시 및 선택을 AI 방식과 동일한 구조로 기록할 수 있어야 한다.
- 종료된 세션에 새 고정 주기 알림이 표시되지 않아야 한다.

## 5. BE 연동 및 데이터 연결

### 5.1 기능별 연동 관계

| FE 동작 | BE 기능 | 주요 전달·반환 정보 |
| --- | --- | --- |
| FE-001·002 목표 확정 및 작업 시작 | BE-001 세션 생성 | goal 전달, sessionId·시작 정보 반환 |
| FE-003 작업 종료 | BE-002 세션 종료 | sessionId 전달, 종료 결과 확인 |
| FE-004·007 방문 및 검색어 전달 | BE-003 방문 기록 저장 | 페이지 정보·검색어·방문 순서·시각 전달 |
| FE-005·006 행동 정보 전달 | BE-006 탐색 행동 정보 갱신 | sessionId·visitId·활성 체류시간·탭 전환 정보 전달 |
| FE-008 최종 분석 결과 수신 | BE-004·007 AI 응답 처리 및 저장 | 세션과 연결된 최종 상태 및 analysisId 수신 |
| FE-008·010 실제 알림 표시 기록 | BE-008 알림 이벤트 저장 | 유형·shownAt 전달, AI 알림만 analysisId 연결, alertId 확보 |
| FE-009 사용자 선택 전달 | BE-005 사용자 선택 결과 저장 | alertId·action·selectedAt 전달 |

BE-009의 탐색 구간 구성은 BE 내부의 역할이며 FE는 구간 구성에 필요한 유효 방문과 행동 정보를 제공하는 영역이다. 외부 API 경로·HTTP 메서드 및 분석 결과 수신 방식은 아직 확정되지 않은 계약이다.

### 5.2 연결 기준

- 세션 생성에 성공한 sessionId를 이후 방문 및 행동 정보에 사용한다.
- 행동 측정값은 올바른 visitId와 세션에 연결한다.
- 분석 결과는 현재 활성 세션과 연결되는지 확인한 뒤 알림에 사용한다.
- 실제 알림의 alertId를 확보하고 사용자 선택에 사용한다.
- AI 알림은 analysisId를 연결하며 고정 주기 알림은 분석 결과 없이 기록한다.

탭 전환은 원본에서 세션 단위 누적이고 BE-006에서는 방문 갱신 정보로도 사용하는 항목이다. 어느 방문에 전환을 귀속할지, 최근 5개 방문 구간의 횟수를 어떻게 산출할지는 FE·BE·AI가 함께 확정해야 하는 계약이다.

원본 FE-001에는 Chrome/Chromium 확장이 언급되어 있으나 첨부 계획서의 성능 보장 범위는 Windows 11의 Google Chrome Desktop Stable에서 수행되는 한국어·영어 목적 지향적 정보 탐색이다. 다른 Chromium 브라우저까지 보장 범위를 확대할지는 별도 확정 사항이다.

위 항목은 원본에 구현 방식이 명시되지 않았거나 FE·BE 연동 과정에서 구체화해야 하는 사항이다. 특히 방문 재개 정책, 행동 정보의 분석 입력 시점 및 종료 흐름은 여러 기능에 영향을 주므로 통합 전에 계약을 맞춰야 하는 항목이다.
