# 데이터 수집 규격

## 1. 개요

Focus Recovery는 사용자가 설정한 작업 목표와 웹 탐색 흐름을 비교하여 집중 상태를 분석하는 서비스이다. 이 문서는 Chrome Extension에서 어떤 탐색 정보를 수집하고, 언제 하나의 방문으로 판단하며, 서버와 AI 분석에 어떻게 전달할지 정의한다.

데이터는 **사용자가 작업 세션을 직접 시작한 동안에만** 수집한다. 세션 종료 후에는 새로운 방문을 수집하거나 알림을 표시하지 않는다. 브라우저 전체 방문 기록을 가져오는 방식은 사용하지 않는다.

역할은 다음과 같이 구분한다.

- **FE(Chrome Extension):** 방문 감지, 본문 추출, 유효성 판단, 체류시간·탭 전환 측정, 전송 큐 관리
- **BE(Spring Boot):** 방문 저장 및 중복 처리, 행동 정보 갱신, 분석 구간(Window) 생성, AI 분석 요청 및 결과 저장
- **AI Service(Python):** 작업 목표와 탐색 흐름을 바탕으로 `NORMAL`, `TRANSITION`, `DRIFT` 분류

## 2. 유효한 페이지 방문 기준

페이지에 접속했다는 사실만으로 방문을 저장하지 않는다. 다음 조건을 **모두 충족**해야 유효한 Page Visit으로 판단한다.

1. 사용자가 시작한 작업 세션이 진행 중이어야 한다.
2. 수집 제외 페이지가 아니어야 한다.
3. 실제 활성 체류시간이 **1초(1,000ms) 이상**이어야 한다.
4. 페이지 종류에 따른 콘텐츠 기준을 충족해야 한다.

| 페이지 종류 | 유효성 기준 |
|---|---|
| 일반 HTML 문서(기사, 블로그, 기술 문서 등) | 전처리 후 주요 본문이 **50자 이상** |
| Google·Naver 검색 결과 | **검색어**와 **유기적 검색 결과 1건 이상**을 추출할 수 있어야 함 |

일반 페이지는 제목만 있고 본문이 없다면 제외한다. 검색 결과 페이지도 검색어만 확인되고 실제 결과를 추출하지 못하면 제외한다. 유효하지 않은 방문은 분석용 `page_visit`에 저장하지 않는다.

### 수집하지 않는 페이지

- `chrome://`, `chrome-extension://`, `file://`, `data:`, `blob:`, `javascript:` 등 일반 웹 문서가 아닌 페이지
- 로그인, 회원가입, 비밀번호 재설정, 인증 토큰 처리 페이지
- 결제·금융·개인정보 입력 중심 페이지
- Chrome 기본 PDF 뷰어 및 영상·음성 콘텐츠 자체
- 오류 화면, 빈 페이지, 콘텐츠 유효성 기준을 충족하지 못한 페이지

민감한 페이지인지 확실하게 판단할 수 없다면 수집하지 않는 것을 원칙으로 한다. 비밀번호, 입력 폼 값, 쿠키, 인증 토큰, 브라우저 저장소, 클립보드, 키 입력 내용은 수집하지 않는다.

## 3. Page Visit 생성 및 재사용

한 번 방문한 페이지를 다시 보거나 새로고침할 때마다 새 방문을 만드는 것은 아니다. 실제로 **다른 탐색 대상에 진입했는지**를 기준으로 판단한다.

| 사용자 행동 | 처리 방식 |
|---|---|
| 새로운 문서에 진입 | 유효성 충족 시 새 방문 생성 |
| 같은 문서 새로고침 | 기존 방문 유지 |
| 뒤로가기·앞으로가기로 다른 문서 이동 | 새 방문 생성 |
| 기존 탭으로 돌아와 같은 문서 확인 | 기존 방문 재개 |
| 같은 탭에서 단순 화면 요소 변경 | 기존 방문 유지 |
| SPA에서 URL과 주요 콘텐츠가 모두 변경 | 새 방문 생성 |
| 분석 제외 페이지로 이동 | 분석용 방문 생성하지 않음 |

새로고침과 탭 복귀 시에는 기존 `visitId`와 `sequence`를 유지하며 활성 체류시간도 이어서 누적한다. 다른 문서로 뒤로가기·앞으로가기를 한 경우에는 이전에 열었던 URL이더라도 새 방문으로 처리한다.

### SPA 페이지

SPA는 전체 페이지를 새로고침하지 않고 주소와 화면을 바꿀 수 있다. 이 경우 **URL 변경과 주요 콘텐츠 변경을 함께 확인**한다. 단순 정렬, 필터, 메뉴 표시, 댓글 펼치기 등은 새로운 방문으로 보지 않는다.

URL의 Query를 제거하면 서로 다른 문서가 같은 정규화 URL을 갖는 경우가 있다. 예를 들어 `?id=100`과 `?id=200`이 다른 게시글을 가리킨다면 콘텐츠 변경 여부를 함께 확인해야 한다. Google·Naver 검색 결과에서는 **검색어가 바뀌었는지**도 탐색 대상 판단에 포함한다.

콘텐츠 변화를 확인할 수 없다면 신규 방문으로 확정하지 않는다. SPA의 구체적인 콘텐츠 비교 방식과 비동기 로딩 대기시간은 구현 단계에서 검증한다.

## 4. URL과 본문 처리

### URL 정규화

서버에는 원본 URL 대신 정규화한 URL을 저장한다.

- `http`와 `https`만 허용한다.
- 호스트명은 소문자로 통일하고 기본 포트는 제거한다.
- 경로(Path)는 의미가 달라지지 않도록 유지한다.
- **Query parameter와 Fragment(`#`)는 제거한다.**
- 인증정보가 포함된 URL이나 민감한 인증 페이지는 수집하지 않는다.

예를 들어 다음 주소는 같은 형태로 저장한다.

```text
원본:   https://Example.com:443/docs/JWT?ref=home#intro
저장:   https://example.com/docs/JWT
```

검색어는 URL에서 Query를 제거하기 **전에** 추출한다. 초기 대상은 Google 검색의 `q`, Naver 통합 검색의 `query` 파라미터다. 실제 지원 URL과 검색 결과 추출 규칙은 샘플 페이지로 검증하며, 원본 Query 전체는 저장하지 않는다.

### 본문 추출

본문은 다음 순서로 처리한다.

1. 페이지에서 주요 콘텐츠를 추출한다.
2. 광고, 메뉴, 푸터, 숨겨진 요소, 스크립트, 입력 폼 등 분석과 관계없는 내용을 제거한다.
3. 불필요한 공백과 줄바꿈을 정리한다.
4. 최종 본문을 **최대 5,000자**로 제한한다.

한국어·영어 본문과 코드의 의미 있는 기호는 보존한다. 단순히 페이지 전체 텍스트의 앞부분을 잘라 사용하는 방식은 피한다. 페이지 로딩이 늦어 본문을 아직 추출할 수 없는 경우에는 재확인하되, 재시도 상한은 구현 단계에서 결정한다.

## 5. 체류시간과 탭 전환

### 활성 체류시간

체류시간은 **해당 탭과 Chrome 창이 모두 활성화되어 있는 동안**만 측정한다. 다른 탭이나 프로그램으로 이동하거나 창이 비활성화되면 측정을 멈추고, 같은 방문으로 돌아오면 다시 누적한다.

- 유효 방문으로 인정하는 최소 활성 시간은 **1초**다.
- 진행 중인 방문은 활성 체류 **10초**가 되면 최초 한 번 분석용 행동 스냅샷을 준비한다.
- 10초 전에 페이지를 떠나거나 세션을 종료하면 그 시점의 행동 정보를 사용한다.
- 실제 방문 이탈 시에는 최종 누적 체류시간을 서버에 반영한다.
- 10초마다 반복해서 같은 방문을 분석하지 않는다.

### 탭 전환 횟수

탭 A에서 탭 B로 이동하면 **이전에 활성화되어 있던 A 방문**의 탭 전환 횟수를 1 증가시킨다. B에서 다시 A로 돌아오면 B 방문에 1을 더하고 A 방문의 체류시간을 재개한다.

같은 탭에서 URL을 변경하거나 백그라운드 탭을 열기만 한 경우는 탭 전환으로 계산하지 않는다. 다른 프로그램으로 이동하는 것도 탭 전환 횟수에 포함하지 않는다.

## 6. 방문 식별자와 행동 정보 갱신

| 필드 | 기준 |
|---|---|
| `visitId` | FE에서 UUID v4로 생성. 재전송 시에도 동일 ID 유지 |
| `sessionId` | 세션 생성 시 발급된 ID 사용 |
| `sequence` | FE에서 실제 방문 후보 발생 순서대로 부여 |
| `browserTabKey` | 세션 내 탭 구분에 사용 |
| `activeDurationMs` | 방문의 누적 활성 체류시간(ms) |
| `tabSwitchCount` | 방문에 귀속된 누적 탭 전환 횟수 |
| `behaviorVersion` | 행동 정보 갱신 시 증가하는 버전 |

`sequence`는 세션 단위로 증가하며, 제외된 방문 후보 때문에 번호가 비어 있어도 다시 매기지 않는다. 여러 탭에서 이벤트가 발생하더라도 중복 번호가 생기지 않아야 한다.

행동 정보는 증가분이 아니라 **누적값**으로 전송한다. BE는 `behaviorVersion`이 현재보다 높은 경우에만 갱신한다. 동일 버전의 동일 요청은 중복 처리하고, 같은 버전인데 값이 다르면 충돌로 판단한다. 오래된 요청이 최신 값을 덮어쓰지 않도록 한다.

## 7. 데이터 전송과 장애 복구

FE는 **IndexedDB**에 방문 후보와 미전송 요청을 보관하고, `chrome.storage.local`에는 활성 세션 정보와 설정을 저장한다.

전송은 다음 원칙을 따른다.

1. 앞선 방문 후보의 유효 또는 제외 판정이 끝난 뒤 후속 방문을 전송한다.
2. 유효 방문을 `sequence` 순서대로 전송한다. 제외된 후보는 보내지 않는다.
3. 서버 저장 확인(ACK)을 받은 뒤 다음 방문을 전송한다.
4. 전송이 실패한 방문이 있으면 후속 방문 전송을 보류한다.
5. 같은 방문을 재시도할 때는 기존 `visitId`를 사용하며, BE는 중복 행과 중복 Window를 생성하지 않는다.
6. 방문 저장이 확인된 다음 해당 방문의 행동 정보 갱신 요청을 처리한다.

네트워크 오류, 시간 초과, 일시적인 서버 오류는 재시도한다. 검증 오류나 데이터 충돌은 무한 재시도하지 않고 확인이 필요한 상태로 남긴다. Chrome Service Worker가 중단되거나 브라우저가 재시작되어도 미완료 요청을 IndexedDB에서 복구한다.

큐의 내부 상태, 재시도 횟수·간격 및 장기 장애 해소 절차는 구현 시 별도로 결정한다.

## 8. Window 생성과 AI 분석

BE는 세션 내 **유효 방문 5개**가 저장되면 `sequence` 순서로 첫 Window를 생성한다. 그다음부터는 새 유효 방문이 하나 추가될 때마다 앞의 방문 하나를 제외하고 다음 Window를 만든다. 즉, Window 크기는 5이고 stride는 1이다.

**Window 생성과 AI 분석은 별개로 처리한다.** Window가 생성되더라도 마지막 방문의 행동 정보가 준비될 때까지 분석을 대기한다. 분석 가능한 시점은 다음 중 하나다.

- 마지막 방문의 활성 체류시간이 **10초**에 도달하여 분석용 스냅샷이 준비된 경우
- 10초 이전에 해당 방문을 떠나거나 세션이 종료되어 행동 정보가 확정된 경우

AI에 전달할 때는 **Window를 구성하는 5개 방문의 입력을 일관된 스냅샷으로 고정**한다. 이 값은 `analysis_result.input_snapshot`에 보존하며, 이후 사용자가 이전 탭으로 돌아가 체류시간이 늘어나더라도 변경하지 않는다. 같은 Window는 행동 정보가 바뀌었다는 이유만으로 자동 재분석하지 않는다.

AI 분석 실패를 `NORMAL`로 간주하거나 임의의 분류 결과로 대체하지 않는다. 세션 종료 이후 도착한 분석 결과는 필요하면 기록하되 새 알림은 표시하지 않는다.

## 9. 세션 종료

사용자가 세션 종료를 선택하면 FE는 즉시 새로운 수집과 알림 표시를 중단한다. 이후 다음 순서로 종료한다.

1. 마지막 방문의 체류시간과 탭 전환 정보를 확정한다.
2. 남은 방문 및 행동 정보 요청을 IndexedDB에 보존한다.
3. 필수 데이터의 서버 저장 확인(ACK)을 모두 받는다.
4. BE에 세션 종료를 요청한다.
5. BE의 `ENDED` 상태를 확인하고 로컬 세션을 정리한다.

네트워크 장애로 전송을 마치지 못했다면 FE는 **`END_PENDING`** 상태로 보관하고 연결 복구 후 전송을 이어간다. `END_PENDING`은 FE 내부 상태이며, BE의 세션 상태는 기존 `ACTIVE`와 `ENDED`를 유지한다.

이미 BE에서 종료한 세션에 미전송 방문이 남은 경우 등 복구 불가능한 상황의 처리 기준은 별도로 정해야 한다.

## 10. 데이터 저장 및 내보내기

서비스 운영 데이터는 기존 관계형 DB와 ERD를 기준으로 저장한다. AI 학습·평가에 사용할 데이터는 다음 형식으로 분리한다.

| 파일 | 내용 |
|---|---|
| `sessions.jsonl` | 익명 참여자, 작업 목표, 세션 정보 |
| `visits.jsonl` | 방문 순서, 정규화 URL, 콘텐츠, 행동 정보 |
| `windows.jsonl` | Window를 구성하는 방문 ID 5개와 순서 |
| `labels.csv` | 평가자가 확정한 `NORMAL`·`TRANSITION`·`DRIFT` 정답 라벨 |
| `features.csv` | 모델 입력에 사용할 수치 특징 |

파일명과 세부 컬럼은 **내보내기 구조의 제안안**이며, 실제 데이터셋 스키마는 구현 시 확정한다. 기본 인코딩은 UTF-8, 체류시간 단위는 ms로 통일하고, 시간값은 UTC 기준으로 내보내는 방향을 권장한다.

학습 데이터에서는 모델의 예측값과 평가자의 정답 라벨을 구분한다. 분석 재현이 필요할 때는 이후 변경된 최종 방문 값이 아니라 **실제 AI 분석에 사용한 입력 스냅샷**을 기준으로 한다. Train·Validation·Test는 작업 목표 단위로 분리한다.

개인정보가 포함된 원본 데이터는 공개 Git 저장소에 올리지 않는다. 데이터셋의 보존기간과 삭제 절차는 별도 정책으로 정한다.

## 11. 구현 전 확인할 사항

다음 내용은 수집 정책의 기본 방향과 별개로, 구현과 테스트 과정에서 추가 확정해야 한다.

- Google·Naver 검색 URL 변형과 유기적 검색 결과 추출 방식
- SPA의 주요 콘텐츠 변경 판정 기준과 비동기 로딩 대기시간
- 작업 세션 시작 당시 이미 열려 있던 탭의 처리 방식
- 탭 식별자 복구와 동시 이벤트에서의 `sequence` 중복 방지
- 영속 큐의 재시도 제한, 장기 오류 및 복구 불가능한 세션 처리
- 분석 스냅샷 생성과 행동 갱신이 겹치는 경우의 동시성 처리
- API 오류 응답 및 `(session_id, sequence)` 유일성 제약 적용 여부
- 데이터셋의 세부 필드, 개인정보 보존기간과 삭제 절차

이 문서는 수집 규칙에 대한 합의 내용을 정리한 것이다. 실제 API 명세·DB 제약·브라우저 이벤트 처리 방법은 각 기능명세와 구현 작업에서 검증하며, 필요한 변경은 별도 Issue 또는 PR로 관리한다.
